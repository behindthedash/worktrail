You are working on **worktrail's test suite** (`tests/`, mirrors `src/worktrail/` package layout).

## Domain purpose
This suite must prove the orchestrator's side-effecting paths (git, `gh`, worker spawn, machine-wide config) behave correctly without ever touching the real machine or network — a failing/flaky test here blocks every PR via CI, and a test that silently passes despite a real bug (self-certification) has repeatedly caused production incidents (see enforcement-coverage tests below).

## Business rules / invariants
- **Never touch real machine-wide state.** `tests/conftest.py`'s autouse `_isolate_go_machine_wide_config` fixture redirects `WORKTRAIL_HOME`, `GO_ROUTING_FILE`, `GO_MODEL_DEFAULTS_FILE`, `GO_AGENT_CAPACITY_CACHE`, and `WORK_QUEUE_DIR` into `tmp_path` for every test. A real populated `~/.worktrail`/`~/.go`/`~/work-queue` broke `test_routing_e2e.py` in production once (2026-08-03) — do not add a new machine-wide config path without wiring it into this fixture.
- **Bare `tempfile.mkdtemp()` never leaks into `/tmp`.** `tests/conftest.py`'s session-scoped autouse `_contain_bare_tempfile_calls` fixture points `tempfile.tempdir` and `TMPDIR` (for spawned subprocesses) at a `tempfile/` dir under pytest's basetemp, which pytest prunes itself. The suite has well over a hundred bare `mkdtemp()` calls with no matching `rmtree`; before this fixture (2026-09-02) ~367k leftover `tmp*`/`preflight-*`/`prepr-*`/`spec-collision-*` entries in `/tmp` stalled systemd-tmpfiles at boot and the WSL user session failed to start. Rely on this containment rather than hand-cleaning each call site, but do not bypass it by hardcoding `/tmp` paths.
- **Hermetic by construction, not by discipline.** Orchestrator tests (`test_verify.py`, `test_integrate.py`, lifecycle harness) inject a fake `run`/`spawn` callable instead of mocking `subprocess` ad hoc — see `FakeRun`/`FakeSpawn` in `test_verify.py` and `tests/orchestrator/lifecycle/fake_gh.py` (a subprocess-level `gh` stand-in placed first on `PATH`, deliberately not a Python-level mock, so the real argument-building/JSON-parsing code paths that broke in prod, #163/#164/#207, actually run).
- **Addon machine-local state is isolated the same way.** `tests/addons/test_aspens.py`'s `_MarkerIsolation` base patches `aspens_module.CACHE_DIR`/`LAST_CHECK_MARKER` to a per-test tempdir — never read/write the real `~/.cache/worktrail/addons/aspens/`. Follow this pattern for any new addon under `src/worktrail/addons/`.
- **A subprocess-level e2e test must scrub `TYPESAFE_API_KEY` from the env it passes down.** `tests/router/test_cluster_dashboard_e2e.py`'s env builder pops it alongside its `GO_CLUSTER_LOG` redirect: `dashboard.py` injects the relatedness judgment into `compute_clusters` whenever a credential is present, so a shell that happens to export one turns those subprocess cluster assertions into live, paid, nondeterministic calls — which is exactly what happened while the judgment was being built (the cluster assertions and `test_json_clusters_deterministic_across_two_runs` all failed because a real verdict replaced the lexical `focus-overlap` signal they pin). Those tests are about the lexical rule; the judgment has its own offline suite.
- **A job whose check-run context is in `required_status_checks` must never carry a job-level `if:` that can skip it on a pull request.** GitHub posts no check-run at all for an `if:`-skipped job, so branch protection sits on "Expected — Waiting for status to be reported" forever and the PR can never merge (PR #653). Gate the individual steps instead. `tests/test_required_check_jobs.py` reads `.github/rulesets/protect-main.json` and every `.github/workflows/*.yml`, and fails on a required context with a job-level `if:` — or with no committed job to post it at all. The one exemption is a job whose `if:` is exactly `github.event_name == 'pull_request'` (`PR_ONLY_GATE`): it only excludes non-PR events, so it never skips on the PR events that report required checks. `gitleaks-pr-diff` in `.github/workflows/gitleaks.yml` relies on this (the same file holds the `workflow_dispatch`-only full-history job).
- **The classifier corpus fixture is generated, redacted, and labelled from run outcomes only — never hand-edited.** `scripts/regenerate_classifier_corpus.py` rebuilds `tests/fixtures/classifier_corpus.json` from the operator's private `~/work-queue`, keeping a brief only when its route came from a run record's `selected_route` (written as `label_source: "actual"`). A brief labelled solely by its own `recommended-route` frontmatter is a machine suggestion, so a ratchet scored against it pins agreement with a guess rather than detecting a routing regression. Regeneration is a deliberate hand-run step and moves the ratchet's `BASELINE_AGREED`/`BASELINE_COMPARED` with it; change the redaction rules in the generator, never the committed fixture directly.
- **The risk-judgment probe fixtures are recorded, not hand-authored, and replay with no key and no network.** `tests/fixtures/risk_probes.json` carries 24 adversarial probes each with a reviewer's `truth` tier; `tests/fixtures/risk_probe_answers.json` carries the answer the judgment service actually returned for each, with the model and capture date in its `_meta`. `tests/router/test_risk_judgment.py` rebuilds the API's response shape from a recorded answer and feeds it through `judge_risk(..., asker=...)`, so `compose_tier()`'s mapping is the part under test and every CI runner (which has no `TYPESAFE_API_KEY`) exercises it. Re-record by re-running the judgment; hand-editing a value makes the test assert a mapping no model produced. The probe `_meta` states the set is deliberately adversarial and measures a capability gap, not a real-world base rate — its pass rates are not accuracy figures for either backend on live briefs.

## Non-obvious behaviors
- **AST-based "enforcement coverage" tests are a load-bearing regression-prevention pattern, not incidental.** `test_gate_enforcement_coverage.py`, `test_policy_key_enforcement_coverage.py`, and `test_pr_creation_callsite_enforcement_coverage.py` AST-walk `src/worktrail` for a specific literal shape (e.g. a `gates.append("...")` call, or a `["gh", "pr", "create", ...]` list literal), assert the discovered set exactly matches a hand-maintained `KNOWN_*`/registered-consumer dict, and behaviorally prove each site is actually enforced — not just present. These exist because the same failure mode (a policy gate computed correctly but silently unconsumed by a new call site) recurred 3-4 times in one week. When adding a new `gh pr create` call site or a new `gates.append(...)` string, you MUST register it in the corresponding test file or the AST-walk test fails immediately. Conversely, when a call site migrates onto `router/land_pr.py` and its `gh pr create` literal disappears, remove its entry from `CALLSITE_CONSUMERS` in the same change (as `drain/drain.py`'s was on 2026-09-05) — the AST walk fails on a registered consumer with no matching literal just as it does on the reverse.
- **Call sites that compose with `land_pr` are tested by monkeypatching the module-level `land_pr` name, not by faking `gh pr create`.** `tests/drain/test_drain.py` sets `drain.land_pr` to a stub returning a `LandOutcome` and asserts on the captured `LandRequest` (`route`, `risk`, `watch_timeout_s`, `title`); `tests/router/test_close_stale_openspec.py` patches `worktrail.router.close_stale_openspec.land_pr` the same way. A non-`landed` outcome in drain is asserted through `sweep_remediations`'s logged `<action> error:` line, not `pytest.raises` on the remediation function.
- **`land_pr._push()` regressions go in `tests/router/test_land_pr_push_refusal.py`, not `test_land_pr.py`.** Tasks 1.1→1.2 of `shared-pr-landing-pipeline` already saturate the compile same-file chain gate on `test_land_pr.py`, so push-refusal detail and explicit-refspec tests were deliberately placed in their own module. Its `LandPrPushRefusalOrchestrationTests` shows the pattern for exercising `land_pr()` end-to-end with every prior step patched at the `land_pr` module seam.
- **Fork-checkout `gh` resolution regressions go in `tests/router/test_land_pr_fork_repo_resolution.py`.** Its `ForkAwareRunner` (a `FakeRun` subclass) reproduces `gh`'s rule that a call without `-R <slug>` addresses the upstream while PR numbers collide across upstream and fork (upstream #15 MERGED, fork #15 OPEN); every assertion reduces to `runner.upstream_calls() == []`. It reuses `FakeRun`/`_land_request` from `test_land_pr.py` and `LandPrResumeTests._run` from `test_land_pr_resume.py` by relative import. Stubs that replace `land_pr._watch_ci` must accept the `base_slug` keyword (see `fake_watch` in `test_land_pr.py`).
- **`test_risk_judgment.py` pins the keyword table's *failure* on the probe set, not just the judgment's success.** `test_the_keyword_table_still_fails_this_probe_set_in_both_directions` asserts exactly 7 unsafe auto-merges and 7 false gates, so if the `RISK_SIGNALS` table is ever fixed to pass those probes the test fails on purpose and the judgment backend's justification has to be re-argued rather than silently inherited. The same module asserts every judged tier error is off by one (never crossing the low/medium → high/critical auto-merge boundary), and proves the default backend never calls out by patching `judge_risk` with `side_effect=AssertionError`.
- **Cluster-signal tests build their signals through production's own `_extract_signal`, not a hand-rolled dict.** `tests/router/test_relatedness_judgment.py`'s `_SignalFixture` writes real brief files to a tempdir and runs them through `cluster_detect._extract_signal(path, _parse_fm)`, so a case cannot silently omit a key (`blocked_by`, `slug`, …) the production dict carries; it overwrites only `stem` afterwards, for readable assertions.
- **Matrix jobs are matched by prefix when resolving a required context to a workflow job.** `tests/test_required_check_jobs.py`'s `_job_for_context` tries exact display-name equality first, then `"<name> ("` prefix, because a matrix job's context carries the interpolated suffix (`"Lint, Test & Build (3.14)"`).
- **The gitleaks signal-integrity script has its own test outside `tests/`.** `scripts/ci/test_check_gitleaks_signal_integrity.py` tests `scripts/ci/check_gitleaks_signal_integrity.py` by running it as a subprocess against canned gitleaks 8.21.2 log text (ANSI codes included) and, for the `--range` cases, against throwaway git repos built with `_commit_history` (base → deletion-only commit → addition commit). The script fails a scan reporting fewer than `--min-commits` commits scanned (an effectively empty range reports "no leaks found" identically to a clean scan), but accepts a zero count when the range is non-empty and no commit in it adds a line (gitleaks counts only commits whose patch adds lines).
- **That script is also vendored as a string constant, hand-synced, with one test standing between the copies.** `worktrail-repo-init` scaffolds it into a target repo from `src/worktrail/onboarding/gitleaks_template.py`'s `CHECK_GITLEAKS_SIGNAL_INTEGRITY_PY` (a raw string, so the script's own regexes survive verbatim) rather than packaged data, so the CLI has no runtime dependency on package-data resolution. There is no automated sync: editing `scripts/ci/check_gitleaks_signal_integrity.py` without updating that constant fails `BuildGitleaksWorkflowTests::test_vendored_script_matches_the_source_of_truth` in `tests/onboarding/test_repo_init.py`, which asserts the two are byte-identical. Same shape as `rulesets_drift_guard_template.py` and `dependabot_manifest_check_template.py`.
- **The committed classifier corpus is re-checked, not trusted because the generator refuses to leak.** `tests/router/test_classifier_corpus_redaction.py` re-runs the generator's own `REDACTIONS` list (plus the repo-name rule built from `~/projects` and `EXTRA_NAMES`) against the *committed* fixture text, asserts every item is `label_source: "actual"`, and reconciles `_meta`'s `item_count`/`per_route` against the items — catching a fixture written by an older generator or hand-edited afterwards. It loads the generator via `importlib.util.spec_from_file_location` for the same reason `test_ruff_pinned.py` does: `scripts/` is not an importable package. Its `RedactionRuleTest` pins the shapes that got through once (a repo name inside a hyphenated compound, a bare `#1687` after a slash), so add a case there when a new leak shape is found rather than only widening the pattern.
- **`testpaths` includes `scripts/ci`, not just `tests` and `hooks`** (added 2026-09-19). A `test_*.py` next to a CI script was previously collected by nothing, so `scripts/ci/test_check_gitleaks_signal_integrity.py` had been green-by-omission since it landed; keep a new CI-script test beside its script rather than moving it under `tests/`. `scripts/ci/test_ruff_pinned.py` and `scripts/ci/test_check_shebang_exec_bits.py` both assert against the real repo as well as fixtures (`test_this_repo_pins_ruff_exactly`, `TestCli::test_forwards_argv_and_runs_the_pinned_ruff`, `test_this_repo_is_clean`) — treat those as live-invariant guards like the `*_selfcheck.py` tests below, not pure unit tests. `test_ruff_pinned.py` loads its subject via `importlib.util.spec_from_file_location` because `scripts/ci/` is not an importable package.
- **`*_selfcheck.py` tests** (`test_automerge_selfcheck.py`, `test_dashboard_selfcheck.py`, `test_journal_selfcheck.py`, `test_policy_drift_selfcheck.py`, `test_policy_selfcheck.py`, `test_quarantine_selfcheck.py`) exercise the corresponding `*_selfcheck` module's own drift/consistency detector against the real repo state — treat these as guarding a live invariant, not just unit-testing a helper.
- **`e2e` tests reuse fixtures across modules via relative imports** rather than reinventing fixture builders — e.g. `test_check_spec_collision_e2e.py` imports `_git`/`_init_repo`/`_make_spec`/`_make_task` from `.test_check_spec_collision` and `QueueTestBase` from `..workqueue.test_work_queue`. Prefer importing an existing fixture builder over duplicating one when writing a new e2e test that spans two subsystems.
- **Golden record/replay regression**: `python3 -m worktrail.orchestrator.orchestrate check` (see AGENTS.md Development section) is a separate check from `pytest` — run both before considering orchestrator changes verified.
- **`tests/router/test_classifier_coverage_ratchet.py` runs in its own CI job, not in `Lint, Test & Build`.** That job (`Classifier Coverage Ratchet`) is a required check as of 2026-09-10, and the main pytest step passes `--ignore=tests/router/test_classifier_coverage_ratchet.py` so it does not run twice per PR — keep both sides in step if the ratchet's location changes.
- **The ratchet materializes fixture items as real brief files and reuses `audit_coverage()` unmodified.** `_materialize()` writes each item's outcome label into the brief's `recommended-route` frontmatter — that field is the transport, not the provenance, because with no run records for fixture briefs it is the only place `audit_coverage()` will read an expected route from. Its `compared` count is asserted exactly (not just `agreed`), so a brief-loading regression that silently drops items cannot show up as a false improvement in the agreement rate.
- **Bash blocks embedded in skill docs are executed, not just string-matched.** `tests/test_plugin_surface.py`'s `_first_bash_block_after(text, marker)` extracts the first ```` ```bash ```` block after a heading/anchor in a skill reference (e.g. `skills/worktrail-go/references/subagent-prompts.md` `#precheck-gate`, `#orchestrator`), and `_run_doc_bash(script, tmp_path, stubs, env)` runs it under `bash -c` with stub `worktrail-*` commands (name → script body) first on `PATH`, so assertions are on the argv/records the block actually produced. Use this when a doc's shell snippet carries branching logic (format detection, `note:` filtering) that a substring assertion cannot prove; the `worktrail-compile` stub prints canned `  note: ...` output via an env var.

## Critical files (purpose, not inventory)
- `tests/conftest.py` — the mandatory isolation fixtures every test in the suite inherits (machine-wide config redirect plus session-wide tempfile containment); read it before writing any test that touches env-resolved paths or scratch dirs.
- `tests/orchestrator/lifecycle/fake_gh.py` — canonical subprocess-level fake for anything that shells out to `gh`; extend its `$GH_FAKE_STATE` JSON schema rather than adding a second fake.
- `tests/router/test_gate_enforcement_coverage.py` / `test_pr_creation_callsite_enforcement_coverage.py` — the reference implementations of the AST-walk + registered-consumer pattern; copy this shape for a new class of "silently unenforced" risk.
- `tests/router/test_land_pr_push_refusal.py` — the designated home for `_push()` / push-refusal regressions and the reference for seam-patched full `land_pr()` orchestration tests.
- `tests/router/test_land_pr_fork_repo_resolution.py` — the designated home for fork-checkout (`remote.pushDefault`) `gh` repo-resolution regressions; `ForkAwareRunner` is the reference for a `gh` fake whose replies depend on which repo a call resolves to.
- `tests/router/test_risk_judgment.py` — the offline home for the risk-tier judgment backend: `compose_tier()`'s pure mapping, every `parse_answers`/`judge_risk` rejection path, both `classify_risk` backends and the fallback between them, and the recorded-probe replay; the reference for testing a module that makes a remote call through an injected `asker` rather than a network-level fake.
- `tests/router/test_relatedness_judgment.py` — the offline home for the brief-relatedness judgment: `should_edge()`'s union rule and threshold boundary, every `judge_pair`/`judge_pairs` failure mode, `_judgment_candidates()`'s selection and ordering and cap, the verdict's effect on an edge in both directions (with structural matches preserved), the stop-on-first-failure rule, `compute_clusters` end to end, and `cluster_telemetry.log_judged_pairs`' record shape and swallowed write failure. No network and no credential: `should_edge` is pure and every end-to-end case injects the verdict; its measured paraphrase / high-overlap-but-unrelated pairs are quoted as fixtures so the cases assert the behaviour the evidence showed.
- `scripts/regenerate_classifier_corpus.py` — the only way `tests/fixtures/classifier_corpus.json` is produced; owns the `REDACTIONS` list, the `EXTRA_NAMES` repo/product aliases that have no machine-readable source, and the outcome-only label rule.
- `tests/router/test_classifier_corpus_redaction.py` — the guard standing between that generator and the public repo; the place to add a case when a new identifier shape survives redaction.
- `tests/test_required_check_jobs.py` — reconciles `.github/rulesets/protect-main.json`'s required contexts against the committed workflow jobs; the place to encode any further "this CI shape makes a required check unsatisfiable" rule.
- `scripts/ci/test_check_shebang_exec_bits.py` — the reference for testing an index-reading gate: `_add()` stages a file and sets its mode with `git update-index --chmod=±x`, so a violation is constructed in git's index rather than via filesystem permission bits (which WSL and a Linux runner disagree about).

## Critical Rules
- Both `unittest.TestCase` (majority, ~130 files) and plain pytest-style functions (~39 files) coexist — match the style already used in the file/subsystem you're editing rather than converting.
- A test that mocks `subprocess`/`gh` ad hoc instead of using `FakeRun`/`fake_gh.py` risks missing the exact argument-building bugs those fakes exist to catch — prefer the existing fake over a new mock.
